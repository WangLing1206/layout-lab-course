# 布局实验室 · Layout Lab —— 网站关键亮点说明

> 一份以**案例驱动**的页面布局教学网站：讲原理、讲取舍、讲「为什么这样排更好」，
> 而不是罗列 CSS 属性。每个知识点都由 **讲解 / 关键代码 / 动态演示** 三块组成，
> 全站中英双语、内容一致，18 个演示全部是可动手操作的真实 DOM 交互。

| 项目 | 内容 |
| --- | --- |
| 在线地址 | https://wangling1206.github.io/layout-lab-course/ |
| 源码仓库 | https://github.com/WangLing1206/layout-lab-course |
| 技术栈 | 原生 HTML + CSS + JavaScript，**无框架、无构建步骤、无第三方依赖** |
| 规模 | 5 章 / 18 个知识点 / 18 个可交互演示 / 双语词条 911 条 / 约 12,100 行源码 |

## 二、最大的亮点：一条案例主线贯穿五章

这是本项目与「CSS 属性手册」类作业的根本差别。

「远山手记」是一份个人技术博客，它的首页**改造前「能用但不好读」**——没有版心、行宽随窗口无限拉长、
三栏写死、标题与正文同级、间距随手给。五章分别解决它的一个阶段：

```
第1章 设计原则   把「好看」变成可执行的规则：对齐 / 留白 / 视觉层次 / 12 栅格
        ↓ 结论：内容先被整理成有层级、有分组、有对齐关系的一堆块
第2章 经典模式   给这堆块选一个骨架：单栏 / 两栏 / 三栏 / 圣杯，以及 F 形 Z 形浏览
        ↓ 结论：博客首页选「两栏 + 通栏头尾」
第3章 Flex & Grid  把骨架搭出来：Grid 负责页面结构，Flex 负责每一排零件
        ↓ 结论：一套 template-areas 描述的版面
第4章 响应式     让这套版面从 320px 到 1600px+ 都成立：移动优先四档 + clamp() 流体排版
        ↓ 结论：四档断点、无断层字号
第5章 案例实战   交付完整代码、改造前后对比、八条验收清单
```

每一章的侧栏都显示**案例进度指示器**（需求 → 骨架 → 实现 → 响应式 → 精修），
读者始终知道自己站在案例的哪一步。第 5 章的 `frame-blog.html` 是一个可以**独立打开、
独立复制**的成品页面，并提供 `?state=before / after` 两种状态做逐块对比。

**为什么这算加分**：布局知识本身是碎的（对齐、间距、断点彼此独立），
只有放进一个真实页面的完整决策链里，读者才能看到「选择 A 会导致什么后果」。
案例把所有零散知识点串成了一条可以复述的故事线。

## 三、每个知识点的固定结构：讲解 / 关键代码 / 动态演示

三块**不是从上到下堆叠，而是等宽三栏切换器**，切换显示其中一栏。

这个设计本身就是一个布局决策：如果三块顺序堆叠，读者想看演示必须先滚过整段代码；
切换器让「讲解—代码—演示」的往返成本变成一次点击，且**切换选择会在同页后续知识点之间记住**，
连续看演示时不用反复点。无 JS 时切换器自动隐藏，三块按原顺序堆叠，**内容不会丢**。

### 3.1 讲解面板：正文列 + 旁注栏的编辑型双栏

正文受 `68ch` 行宽上限约束——**不为了填满容器而把行拉长**（这正是在教行宽）。
因此宽面板右侧会空出一块，与其浪费，不如把「提示」与「设计权衡」移到右侧旁注栏。
容器不够宽时（`@container` 判定 < 860px），旁注栏自动落回正文之后、以细线分隔。

这个面板自己就是第 4 章「容器查询」的真实用例——
**组件关心的是「我被放进多宽的容器」，而不是「视口有多宽」**。

### 3.2 关键代码：带注释、可复制、注释也跟着翻译

代码块带语法着色与一键复制，要点以列表单独解释。
注释通过逐文本节点着色实现翻译——着色器遍历 `pre code` 的文本节点，
但**跳过带 `data-i18n` 的子树**，因此一条注释可以被单独翻译，语言切换时只替换那一个节点。

### 3.3 动态演示：每个演示下方都有一段「跟着你重写的 CSS」

这是本项目交互设计的核心。每个演示下方固定有一块 **「实时输出」代码块**，
它跟着你的每一次拖动、点击同步重写：

> **把参数调到满意，直接复制那段 CSS 就能用在自己的页面上。**

演示区展示的从来不是「演示效果」，而是**你刚才那一步操作对应的等价 CSS**。
这把「动手玩」和「拿到代码」之间的落差抹掉了。

## 四、18 个可交互演示清单

| 章 | 知识点 | 演示 | 交互方式 |
| --- | --- | --- | --- |
| 1 | 对齐 | 对齐方式开关 + 参考线 | 切换 `align-items` 四种值、文本对齐；打开列参考线与基线参考线；关掉对齐后能看到 3–9px 的随机偏移如何毁掉版面 |
| 1 | 留白 | 留白与接近性 | 拖动间距刻度滑块，切换「成组 / 不成组」，直观看到组间 > 组内时读者才会把卡片内容看成一「组」 |
| 1 | 视觉层次 | 层级比例尺 | 拖动倍率（决定整套字号）、字重滑块、次级信息透明度，四个层级实时重算 |
| 1 | 栅格系统 | 12 栅格 | 列数滑块实时重建参考线，正文/侧栏/卡片的跨列数跟着重算 |
| 2 | 单栏与行宽 | 行宽测量 | 拖动版心宽度，实时算出「一行约几个汉字 / 几个西文字符」，并判断是否落在 45–75 可读区间 |
| 2 | 经典模式 | 五种模式一键切换 | 单栏 / 两栏（右）/ 两栏（左）/ 三栏 / 圣杯一键切换，**并对比 Grid 与 Flex 两种实现** |
| 2 | F 形 Z 形 | 眼动路径动画 | 切换 F 形与 Z 形，SVG 折线按实际长度「一笔画完」地播放扫读路径 |
| 3 | 主轴交叉轴 | Flex 试验台 | `flex-direction` / `wrap` / `justify-content` / `align-items` / `align-content` / `gap` 全部可调；轴标签随方向自动换位；可勾选哪些项目吸收剩余空间 |
| 3 | 轨道与 fr | Grid 试验台 | 列定义（3 等分 / 1fr2fr1fr / 固定+弹性 / auto-fill+minmax）切换，`justify-items`/`align-items` 可调 |
| 3 | 命名区域 | `grid-template-areas` 画笔 | **在 3×3 画板上点击涂色**，实时校验同名区域是否构成矩形；非法时预览「散架」，并在代码里说明 CSS 会丢弃整条声明 |
| 3 | 选型思路 | 选型决策器 | 回答「一维还是二维 / 要不要跨卡片对齐 / 尺寸由内容还是版面决定」，给出 Flex 或 Grid 的结论与理由 |
| 4 | 断点设计 | 视口模拟器 | **拖动视口宽度滑块**，真实 iframe 按媒体查询重排，断点标尺高亮当前档位并解释该档的设计意图 |
| 4 | 流体排版 | `clamp()` 试验台 | 分别调 min / vw 系数 / rem 项 / max，用与 CSS 相同的公式算出当前实际字号，并判断处于下限、流动区间还是上限 |
| 4 | 容器查询 | 容器查询 vs 媒体查询 | 同一个卡片组件并排两份：左边用 `@container`、右边用 `@media`，拖动容器宽度看两者行为分叉 |
| 5 | 需求 → 骨架 | 线框增删 | 勾掉页头 / 正文流 / 侧栏 / 页脚任意区域，实时看到骨架列数与取舍结论变化 |
| 5 | 骨架选型 | 方案对比 | 单栏 / 两栏 / 三栏三方案切换，给出各自的容量与阅读性代价 |
| 5 | 完整成品 | 成品预览 | 真实 iframe 加载案例成品，可用视口预设 375 / 768 / 1024 / 1280 查看重排，也可新标签页打开 |
| 5 | 精修 | 改造前后对比 | 同一份代码切换 `before` / `after`，七处修正的差别一目了然，并附逐条说明 |

**实现方式**：所有演示共用一个约 200 行的控件工具箱——滑块 / 分段按钮 / 开关统一派发
`lab:change` / `lab:seg` / `lab:toggle` / `lab:ready` 事件，每个演示只需回答
「数据变了以后怎么改样式」，并调用 `api.code()` 把等价 CSS 打印到实时输出块。
因此新增一个演示的成本很低，而 18 个演示的行为高度一致。

## 五、双语的实现：一份 HTML + 一份英文对照

**中文直接写在 HTML 标签里，英文放配置对象。** 这样做的三个好处：

1. **禁用 JS 时页面依然完整可读**（也利于 SEO 与无障碍）；
2. 只维护「一份 HTML + 一份英文对照」，不存在中英两份 HTML 逐渐漂移的问题；
3. 切换语言时用 `data-i18n` 标记覆盖为英文，切回中文则**还原首次加载时抓取的原文**——
   不需要把中文再抄一遍。

```
data-i18n="key"             替换 textContent
data-i18n-html="key"        替换 innerHTML（含行内标签时用）
data-i18n-attr="attr:key"   替换属性（可逗号分隔多组）
```

JS 动态生成的文案（演示读数、状态提示）放在同一个文件的 `UI` 表里，中英各一份。

### 5.1 一个特别处理：实时输出代码块里的注释

「实时输出」的 CSS 是 JS 拼出来的，注释里嵌着动态数值（间距 px、断点名称、列数……）。
中英语序不同，**不能靠字符串拼接**，所以整句作为词条、用 `{n}` 占位符取值：

```js
t("c.space.outer", { n: outer.toFixed(0) })
// zh: 组与组之间 30px      en: 30px between groups
```

站内共 91 行这样的注释已全部词条化。**英文模式下扫描全部实时代码块，中文残留为 0**
（见第六节的验证结果）。

### 5.2 缺译文时优雅退回

`t()` 的查找顺序是「当前语言 → 中文 → 键名本身」，因此漏译**不会出现空白或 `undefined`**。
仓库还带一个自检脚本，漏译时以非零退出码结束，可直接用于 CI：

```bash
node tools/check-i18n.mjs          # 校验：列出漏译与多余词条
node tools/check-i18n.mjs --list   # 列出全部词条与中文原文，便于翻译
```

## 六、本站如何示范所讲的布局方法

作业要求之一是「**网站本身必须是所教布局方法的良好示范**」。
下面每条都可以在仓库里逐条核对，全部是原生实现：

| 技术 | 用在哪里 |
| --- | --- |
| CSS 自定义属性 | `tokens.css` 统一管理颜色 / 间距 / 字号 / 圆角；暗色主题**只覆盖令牌**，组件样式一行不改 |
| Grid | 整站骨架（目录栏 + 正文栏）、知识点三栏切换器、卡片阵列（`auto-fit`）、演示区、案例骨架与断点重排（`template-areas`） |
| Flexbox | 顶栏、控件行、开关组、卡片内部、页脚——凡是「一排东西」都用 Flex，靠边用 `auto` margin |
| `clamp()` | 字号刻度 `--step--1 … --step-5` 全部是流体值，320px → 1600px 之间**没有字号断层** |
| 容器查询 | 两处真实用途：第 4 章的对照演示，以及**讲解面板自身**（容器 ≥860px 才把旁注栏并排到右侧） |
| 逻辑属性 | `margin-inline` / `padding-inline` / `border-inline` 全站使用，版面天然支持从右到左的语言 |
| `position: sticky` | 顶栏、章节目录、案例侧栏（均配 `align-self: start`，否则在 Grid 里会失效） |
| `aspect-ratio` | 缩略图与模拟视口按比例而非固定宽高，避免加载与缩放时的布局跳动 |
| 无障碍 | 语义化标签、skip-link、`:focus-visible` 焦点环、`aria-live` 播报演示读数、尊重 `prefers-reduced-motion` |
| 移动优先 | 320px → 1600px+ 均可读；断点内用 `min-width` 递进 |

**没有一行布局是用框架生成的**，也没有构建步骤——克隆下来直接打开就能读。

## 九、本地运行与校验

```bash
# 任意静态服务器均可（不要用 file:// 打开，iframe 演示需要 http 环境）
python -m http.server 8000      # 然后访问 http://localhost:8000

# 双语完整性检查
node tools/check-i18n.mjs
node tools/check-i18n.mjs --list
```

### 已知边界

- 案例成品 iframe 用了一份自成一体的小字典（内联在 `frame-blog.html` 里），
  以便这份成品可以被单独打开、单独复制使用，不依赖主站脚本。
- 容器查询、`text-wrap: balance/pretty`、`dvh` 等较新特性在不支持的浏览器里会优雅退化为默认行为。
